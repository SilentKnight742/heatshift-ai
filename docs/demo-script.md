# Product demo walkthrough

Target: 3–4 minutes.

## 1. Problem and evidence — 35 seconds

Open the homepage. Say: “A weather map tells an operations manager where it is hot. HeatShift decides which work can move without breaking the operation.” Show the five-stage flow, the three decision dimensions and the HEAT-SHIELD result. State that the research supports screening prioritization through association, not injury prevention.

## 2. Map-first console — 35 seconds

Open Console. Point to the provider status in the header. If it says Simulated run, explain the stated reason and that Retry is a fresh read-only check; the map remains usable. Choose Arizona and DesertLine. Pan, zoom, scrub the hour and click a heat cell to show exact temperature and work inside it.

## 3. Existing result — 45 seconds

Switch Original and HeatShift. Show active-work outlines, then open Exposure reduction and one other metric. Explain that the metric panel and agent panel can remain open, move independently and collapse to their headers. Open Operation & method to show crews, jobs, weather, formulas, constraints and job-level before/after changes.

## 4. Create a new operation — 60 seconds

Return to the map, choose any state and create a site by double-click or coordinates. Select a historical date. Say clearly that custom-site weather is simulated and labelled as such. Choose the seed and operation size, generate crews/jobs, then run HeatShift analysis. Show the new heat cells, briefing, proposal and zero hard violations.

## 5. Explain the result — 35 seconds

Say:

- Site Thermal Burden describes daily heat intensity and persistence.
- Crew Exposure Load shows cumulative risk-weighted worker-hours.
- Operational Disruption reports shifted minutes and crew changes separately.

The briefing explains the deterministic result; it cannot alter the official schedule or metrics.

## 6. Boundary — 20 seconds

End with: “HeatShift is historical screening-level planning support. It is not a forecast, sensor, medical system or replacement for on-site WBGT and qualified safety judgment.”

## Pass/fail before recording

- Header accurately shows Checking, Simulated run or FortyGuard live.
- Retry leaves fallback active on failure and exits it only on success.
- No provider modal blocks the map.
- Cell temperatures and shades respond to the hour while the state scale remains fixed.
- Custom site → simulation → analysis completes.
- Original and HeatShift remain separate; hard violations stay zero.
- Markdown renders without raw asterisks or executable HTML.
- Desktop and mobile layouts remain readable without page overflow.
