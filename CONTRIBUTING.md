# Contributing to HeatShift AI

## Branch conventions

- Use `main` for the initial backend completion and deployment checkpoint.
- Use `kirmadaLinux` when a personal integration branch is preferable to direct work on `main`.
- Use production-style, descriptive branch names for scoped work:
  - `feature/<descriptive-kebab-case>`
  - `fix/<descriptive-kebab-case>`
  - `chore/<descriptive-kebab-case>`
  - `release/<version-or-descriptor>`
- Do not create or use a branch named `codex`.

Keep commits focused, run the relevant tests before pushing, and never commit API keys or
other credentials.
